Under the hood

Line-Following Algorithm

A reactive PD controller running at 10 Hz. No map, no path plan — just the current camera frame, two geometric error signals, and a turn-rate command.

Camera Frame — Lateral Error

Bird's-Eye View — Both Error Signals

Two Error Signals

e_lat = (cₓ − w/2) / (w/2) ∈ [−1, 1]
e_hdg = atan2(v̂ₓ, v̂ᵧ) / 90° ∈ [−1, 1]

Lateral error — how far the line's centroid sits from the horizontal centre of the frame.

Heading error — angle between the cv2.fitLine direction and the camera's vertical axis (robot's forward). Positive = line tilts right = robot is turned left of the line.

PD Control Law

ω = −( Kp·e_lat + Kd·ė_lat + Kp_hdg·e_hdg )
vₓ = v_base · (1 − γ · min(|e_lat|+|e_hdg|, 1))

The heading term makes correction predictive: it starts realigning the body angle before lateral drift grows large, cutting overshoot on curves. Speed scales down with total misalignment so the robot slows on tight turns.

Parameter Default Effect
kp60.0 Proportional lateral gain — higher corrects drift faster but risks oscillation.
kp_heading30.0 Heading gain — aligns body angle with the line before lateral error grows.
kd8.0 Derivative damping — reduces overshoot as the robot approaches centre.
base_speed30.0 Forward duty at zero error.
turn_reduction0.6 Fraction of base speed removed when combined misalignment reaches 1.0.
roi_top0.4 Top of the look-ahead region as a fraction of frame height.
lost_timeout2.0 s Time without a detected contour before full stop.
memory_duration0.6 s Coast duration — last commands held while the line is briefly invisible.

Built-in safety

Camera-Based Obstacle Avoidance

No extra sensors — the same camera frame used for line following detects obstacles too. A floor colour model built fresh every tick separates floor, line tape, and foreign objects.

↳ obstacle detected → Stop + Beep — skips the PD controller for that tick; resumes automatically when the path clears.

Camera Frame — Detection Zones

Colour-Space Detection Concept

Floor Colour Sampling

c_floor = median { BGR(i,j) :
i ∈ [0.85h, h), j ∈ [0.25w, 0.75w) }

Sampled from the bottom 15 % of the frame — always bare floor right in front of the robot. The median is robust to the coloured line tape that may appear in the strip. Recomputed every tick so lighting changes are handled automatically with no calibration step.

Obstacle Presence Fraction

f_obs = (1/|Z|) Σ 𝟙[ d(i,j) > τ_color
∧ L(i,j) = 0 ]
trigger: f_obs > τ_presence → stop + beep

d(i,j) is the BGR Euclidean distance from c_floor. L(i,j) is the line-colour HSV mask — it excludes tape pixels to prevent false stops. Both conditions must hold for a pixel to count as an obstacle.

Flag Default Effect
--obstacle-stopoff Enable obstacle detection. Off by default — add this flag to activate.
--obstacle-color-thresh40.0 BGR Euclidean distance threshold τ_color. Lower = more sensitive; raise on textured or unevenly-lit floors.
--obstacle-presence-thresh0.25 Fraction of the detection zone that must be non-floor, non-line to trigger a stop. Lower = reacts to smaller objects.
# Line following with obstacle avoidance
$ python -m client.line_follow \
--robot-ip 192.168.88.100 --colour red --obstacle-stop
 
# With PS5 override + obstacle avoidance (PS5 bypasses the obstacle check)
$ python -m client.line_follow \
--robot-ip 192.168.88.100 --colour red \
--controller ps5 --obstacle-stop

What it does

Everything you need to build a walking robot brain

From raw data collection to trained policies — the full pipeline runs on a laptop talking to a Jetson-based hexapod over Wi-Fi.

🎮

PS5 Teleop

Drive the hexapod with a DualSense controller via Bluetooth. Left stick moves, right stick rotates, cross button emergency-stops.

〰️

Colour Line Following

Vision-based line follower for red, white, and blue floor lines. Uses cv2.fitLine to align the robot's heading with the line direction — not just the centroid.

🕹️

PS5 Manual Override

While line-following, move any stick to take manual control instantly. Release and the robot resumes autonomous following.

📹

Episode Recording

Record labelled teleop episodes at 10 Hz. Accept or discard each episode with arrow keys or the PS5 controller before saving.

🧠

CNN Policy

Train an image-based CNN policy from collected episodes. Evaluate checkpoints locally and deploy to the robot in real time.

🤗

LeRobot Export

Export any recorded session to Hugging Face's LeRobot dataset format for use with large Vision-Language-Action models.

📡

ROS 1 Integration

Motor controller publishes to /cmd_vel, /state, and /head_scalar — compatible with the hexapod's C++ controller node.

📷

Orbbec RGB+Depth

Serves the Orbbec Astra's colour stream via a ROS topic fallback when V4L2 is unavailable. Depth data exposed for future obstacle avoidance.

🛡️

Safety Features

Motor watchdog stops the robot if commands time out. Auto sit-down on server shutdown. Stand-up sequence runs automatically at startup.

How it works

System Architecture

The laptop talks to a Flask HTTP server on the robot. The server bridges HTTP commands to ROS 1 topics consumed by the hexapod's C++ controller.

┌─────────────────────────────────────────────────────────────────┐ │ LAPTOP (macOS / Linux) │ │ │ │ PS5 DualSense ──► PS5Controller ──┐ │ │ Keyboard ──► TeleopController ──┤ │ │ ├──► RobotClient (HTTP) │ │ LineFollower ──┤ POST /velocity │ │ CNNPolicy ──┘ GET /snapshot │ │ │ └───────────────────────────────┬─────────────────────────────────┘ │ Wi-Fi (HTTP :8080) ┌───────────────────────────────▼─────────────────────────────────┐ │ ROBOT (Jetson TX1 · ROS Melodic) │ │ │ │ Flask HTTP Server │ │ ├── /velocity ──► MotorController │ │ │ ├── pub /cmd_vel (geometry_msgs/Twist) │ │ │ ├── pub /state (std_msgs/Bool) │ │ │ └── pub /head_scalar │ │ │ │ │ └── /snapshot ◄── ROSCameraCapture │ │ └── sub /camera/color/image_raw │ │ │ │ Hexapod_Controller (C++) ◄── /cmd_vel, /state │ │ ros_astra_camera ──► /camera/color/image_raw │ └─────────────────────────────────────────────────────────────────┘

Get up and running

Quick Start

Five steps from clone to driving the robot.

1

Clone and create the venv

Requires Python 3.10+ on the laptop.

2

Install laptop dependencies

pip install -r requirements-laptop.txt

3

Deploy server to the robot

ROBOT_IP=x.x.x.x bash scripts/deploy_server.sh start

4

Drive with keyboard or PS5

python -m client.teleop --robot-ip x.x.x.x --controller ps5

5

Start line following

python -m client.line_follow --colour red --controller ps5

# 1. Clone
$ git clone https://github.com/MichaelAguadze/hexapodvla
$ cd hexapodvla
 
# 2. Install (laptop)
$ python3 -m venv venv && source venv/bin/activate
$ pip install -r requirements-laptop.txt
 
# 3. Deploy server to robot
$ ROBOT_IP=192.168.88.100 bash scripts/deploy_server.sh start
 
# 4. PS5 teleop
$ python -m client.teleop \
--robot-ip 192.168.88.100 --controller ps5
 
# 5. Line follow (red, PS5 override)
$ python -m client.line_follow \
--robot-ip 192.168.88.100 --colour red --controller ps5
